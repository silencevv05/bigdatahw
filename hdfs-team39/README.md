# Автоматическое развёртывание HDFS — team-39

Учебный кластер Apache Hadoop **3.4.0** (полный официальный архив) на **Ubuntu 24.04.5**, OpenJDK 11. Все Hadoop-службы работают под **отдельным непривилегированным системным пользователем `hdfs`**, а доступ к серверам и установка выполняются через `team` и его `sudo`. Данные сохраняются между перезапусками.

## Архитектура

| Сервер | Адрес | Роль |
|---|---|---|
| `team-39-en` | `10.39.0.10` | SSH jump-host / запуск скрипта |
| `team-39-nn` | `10.39.0.11` | NameNode, SecondaryNameNode и DataNode |
| `team-39-00` | `10.39.0.12` | DataNode |
| `team-39-01` | `10.39.0.13` | DataNode |

**Три DataNode на трёх внутренних VM.** На NameNode хранятся метаданные в `/var/lib/hdfs/name`, на DataNode — блоки в `/var/lib/hdfs/data`; программные файлы в `/opt/hadoop`, логи в `/var/log/hdfs`. Репликация по умолчанию: `3`. SecondaryNameNode делает checkpoints и **не** обеспечивает HA.

## Отличия от ручного варианта

Нет ручного `adduser`, копирования `~/.ssh` или `start-dfs.sh`: созданием `hdfs` управляет `useradd --system`; SSH от `hdfs` не нужен, потому что edge запускает команды удалённо от `team`, а systemd запускает процессы как `hdfs`. Системный пользователь получает оболочку `/usr/sbin/nologin`, без пароля и sudo. Рабочие данные не хранятся в `/home/team`. HDFS запускается сервисами `Type=simple` с перезапуском при ошибках. Edge не хранит HDFS-блоки.

## Предусловия

- Со своего ПК: `ssh team@111.88.131.73`.
- На edge: `~/.ssh/team_internal` обеспечивает доступ к `team` на трёх внутренних VM и `sudo -n true` проходит без пароля.
- Внутренние серверы могут скачивать пакеты Ubuntu через apt, edge может скачать дистрибутив Apache.
- **Запуск только для пустой учебной среды**. Не запускайте поверх уже существующего HDFS без отдельного плана миграции; скрипт блокирует некоторые случаи существующих метаданных.

## Запуск

Из Windows PowerShell, находясь в каталоге с распакованной папкой проекта:

```powershell
scp -r .\hdfs-team39 team@111.88.131.73:~/
ssh team@111.88.131.73
```

На edge:

```bash
cd ~/hdfs-team39
bash scripts/deploy.sh
bash scripts/check.sh
```

`scripts/deploy.sh` устанавливает Java 11, проверяет SHA-512 для официального архива Hadoop, создаёт `hdfs` **на внутренних VM**, копирует конфигурации, создаёт systemd-сервисы, один раз форматирует новый NameNode и запускает пять демонов. Повторный запуск не форматирует обнаруженные метаданные заново, но автоматическое восстановление частично сломанного кластера не обещается.

`scripts/check.sh` проверяет пять сервисов, число живых и мёртвых DataNode, запись и чтение, наличие трёх реплик тестового файла и `fsck`. Результат `PASS` ожидается только после реального успешного запуска на предоставленных VM.

## Диагностика

На edge:

```bash
ssh -i ~/.ssh/team_internal team@team-39-nn 'sudo systemctl status hdfs-namenode hdfs-secondary hdfs-datanode --no-pager'
ssh -i ~/.ssh/team_internal team@team-39-00 'sudo journalctl -u hdfs-datanode -n 80 --no-pager'
ssh -i ~/.ssh/team_internal team@team-39-nn 'sudo -u hdfs /opt/hadoop/bin/hdfs dfsadmin -report'
```

Работа под `hdfs` проверяется `ps -eo user,comm,args | grep -E "NameNode|DataNode"` или `systemctl show -p User hdfs-datanode.service`.

## Безопасность и ограничения

- HDFS не настроен для Kerberos. Это **закрытый учебный стенд**; не публикуйте служебные порты в интернет.
- `team` сохраняет право sudo для установки, `hdfs` — нет.
- Сервисы `hdfs-*` стартуют при загрузке ОС (`systemctl enable --now`).
- **Не выполнять `hdfs namenode -format` на существующих данных**. Скрипт отказывается форматировать непустой каталог с отсутствующим `VERSION`.
- Для сдачи добавьте фактический скриншот NameNode UI и вывод проверки в `evidence/` и разместите этот проект в публичном GitHub-репозитории. Не коммитьте приватные ключи, `.cache/`, логи и данные HDFS.

Источники: [официальный архив Hadoop 3.4.0](https://archive.apache.org/dist/hadoop/common/hadoop-3.4.0/), [документация](https://hadoop.apache.org/docs/r3.4.0/).

**Совместимость:** для Hadoop 3.4.0 используется OpenJDK 11. Версия архива `hadoop-3.4.0.tar.gz` (не `lean`): в официальном каталоге 3.4.0 отсутствует lean-архив. Архив около 921 МБ, на edge и внутренних узлах нужно достаточно места и трафика.

## Результаты на тестовой среде (12.10.2026)

Успешно пройдена автоматическая проверка: `Live datanodes (3)`, запись и чтение тестового файла, три реплики, `fsck` со статусом `HEALTHY`. Подробности: [REPORT.md](REPORT.md). На стенде также настроены `dfs.namenode.rpc-bind-host` и `dfs.namenode.http-bind-host` для доступа к RPC и веб-интерфейсу через внутреннюю сеть.

**Примечание:** DataNode на сервере NameNode пока объявляет `127.0.0.1`; это ограничение отражено в отчёте и требует дополнительной настройки для удалённых HDFS-клиентов.
