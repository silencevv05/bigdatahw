# Итоговый отчёт: автоматизированное развёртывание кластера HDFS

**Работа:** развёртывание Apache Hadoop HDFS с тремя DataNode, NameNode и SecondaryNameNode  
**Учебная среда:** `team-39`  
**Дата проверки:** 12 октября 2026 года  
**Результат:** кластер развёрнут; автоматическая проверка завершена успешно (`PASS`).

## 1. Цель

Автоматизировать установку и конфигурирование распределённой файловой системы HDFS, включающей три работающих DataNode, NameNode и SecondaryNameNode. Подтвердить работоспособность командной проверкой количества узлов и операциями чтения, записи и репликации данных.

## 2. Программное обеспечение и среда

- ОС: Ubuntu 24.04.5 LTS, четыре виртуальные машины (одна edge-нода и три внутренних узла).
- Apache Hadoop 3.4.0.
- OpenJDK 11.
- Bash, SSH/SCP, systemd.
- Отдельный системный пользователь `hdfs` для запуска Hadoop; пользователь `team` — для административных операций и входа по SSH.

## 3. Архитектура

| Сервер | Внутренний IP | Назначение |
| --- | --- | --- |
| `team-39-en` | `10.39.0.10` | SSH jump-host, запуск автоматизации |
| `team-39-nn` | `10.39.0.11` | NameNode, SecondaryNameNode, DataNode №3 |
| `team-39-00` | `10.39.0.12` | DataNode №1 |
| `team-39-01` | `10.39.0.13` | DataNode №2 |

Всего запущено пять Hadoop-демонов: один NameNode, один SecondaryNameNode и три DataNode. Третий DataNode размещён на той же учебной VM, что и NameNode. SecondaryNameNode выполняет checkpoint метаданных и **не** заменяет NameNode в режиме высокой доступности.

Расположение компонентов: Hadoop — `/opt/hadoop`, метаданные NameNode — `/var/lib/hdfs/name`, блоки DataNode — `/var/lib/hdfs/data`, журналы — `/var/log/hdfs`. Коэффициент репликации новых файлов по умолчанию: **3**.

## 4. Автоматизация

Проект содержит:

| Артефакт | Назначение |
| --- | --- |
| `scripts/deploy.sh` | Проверка SSH и sudo, скачивание и проверка SHA-512 архива, передача файлов, инициализация и запуск служб |
| `scripts/remote-setup.sh` | Установка Java и Hadoop, создание пользователя `hdfs` и системных каталогов |
| `scripts/common.sh` | Функции SSH/SCP и переменные узлов |
| `scripts/check.sh` | Проверка служб, DataNode, записи/чтения, репликации и `fsck` |
| `configs/core-site.xml` | Адрес HDFS/NameNode |
| `configs/hdfs-site.xml` | Каталоги NameNode/DataNode, репликация и сетевые привязки |
| `configs/workers` | Перечень узлов DataNode |
| `systemd/*.service` | Управление пятью демонами через systemd |
| `README.md` | Инструкция по установке и воспроизведению |

Сценарий развёртывания запускается на `team-39-en`:

```bash
cd ~/hdfs-team39
bash scripts/deploy.sh
```

При первом развёртывании NameNode форматируется только при отсутствии метаданных. Повторное форматирование существующего пространства имён запрещено.

## 5. Возникшие проблемы и исправления

1. **Удалённые DataNode не регистрировались в NameNode.** NameNode принимал RPC-соединения только на локальном адресе `127.0.1.1:8020`; удалённые узлы пытались подключиться к `10.39.0.11:8020`. Добавлен параметр `dfs.namenode.rpc-bind-host=0.0.0.0`, после перезапуска NameNode все три DataNode зарегистрировались.
2. **Автоматическая проверка ожидала строку `Dead datanodes (0)`.** Hadoop не выводил эту секцию при отсутствии мёртвых узлов. `check.sh` исправлен: он проверяет наличие `Live datanodes (3)` и отсутствие положительного количества `Dead datanodes`.
3. **Web UI NameNode был недоступен через SSH-туннель.** Добавлен параметр `dfs.namenode.http-bind-host=0.0.0.0`; доступ к интерфейсу через `localhost:9870` заработал.

Настройки привязки `0.0.0.0` применяются только во внутреннем учебном контуре. RPC/HTTP-порты Hadoop не следует открывать напрямую в интернет.

## 7. Ограничения

- Кластер предназначен для учебной изолированной сети. Kerberos и отказоустойчивый NameNode (HA) не настраивались.
- DataNode, совмещённый с NameNode, в проверенном запуске объявлял `127.0.0.1:9866`. Для сценариев, где удалённые клиенты обращаются непосредственно к этому DataNode, следует дополнительно настроить его объявляемый адрес на `10.39.0.11` и повторить проверку. Успешный локальный тест не доказывает доступность этого DataNode всем внешним HDFS-клиентам.
- Скрипты рассчитаны на предоставленный стенд и не выполняют автоматическую миграцию существующего кластера.
- Публикуемый репозиторий не должен содержать SSH-ключей, кэша дистрибутива, содержимого `/var/lib/hdfs` и приватных журналов.
