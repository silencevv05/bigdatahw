# ДЗ 5. Обработка данных через Prefect

Здесь собраны код и скрипты для обработки заказов на учебном кластере
`team-39`. Используются Prefect 3.9.3, Apache Spark 3.5.7 и Java 11.
Prefect запускает приложение Spark под управлением YARN, а результат
сохраняется в таблицу Hive.

За основу взято приложение из [ДЗ 4](../spark-team39/README.md).
В этом задании добавлен поток Prefect с проверкой входного файла,
запуском Spark и независимой проверкой результата через Hive.

## Что где работает

| Компонент | Где работает | Что делает |
| --- | --- | --- |
| Prefect | `team-39-en` | Управляет последовательностью задач |
| Spark Driver | `team-39-en` | Выполняет приложение в режиме `client` |
| YARN | Кластер из ДЗ 2 | Выделяет ресурсы для Spark |
| Spark Executors | `team-39-00`, `team-39-01` | Выполняют обработку данных |
| HDFS | Кластер из ДЗ 1 | Хранит исходные данные и результат |
| Hive | Сервисы из ДЗ 3 | Хранит метаданные и предоставляет SQL-доступ |

Используется установленный Spark в `/opt/spark-team39`.
Его конфигурация находится в `/etc/spark-team39`, Hadoop — в
`/opt/hadoop`, конфигурация Hadoop — в `/opt/hadoop/etc/hadoop`.

Параметры подключения и функции запуска находятся в
`scripts/common.sh`. Для Hive используются `/opt/hive`,
`/opt/hive-java8`, `/etc/hive-team39/client` и
`/etc/hive-team39/hadoop`.

## Что нужно до запуска

Команды выполняются на `team-39-en` от пользователя `team`.
Нужны работающие HDFS, YARN, Hive Metastore и HiveServer2,
а также возможность выполнять `sudo` без пароля.

В HDFS должен находиться подготовленный в предыдущем задании файл
`/data/team39/spark/input/orders.tsv`.

Файл содержит пять столбцов без заголовка, разделённых табуляцией.

| Столбец | Содержание |
| --- | --- |
| `order_id` | Идентификатор заказа |
| `customer_id` | Идентификатор покупателя |
| `amount` | Сумма заказа |
| `order_date` | Дата в формате `yyyy-MM-dd` |
| `country` | Код страны |

## Установка Prefect

Из папки `prefect-team39` выполнить:

```bash
sudo apt-get update
sudo apt-get install -y python3.12-venv
python3 -m venv ~/venvs/hw_5
~/venvs/hw_5/bin/python -m pip install -r requirements.txt
```

Для Prefect используется отдельное Python-окружение `hw_5`.
Spark запускается с системным `/usr/bin/python3`.

## Запуск обработки

Из папки `prefect-team39` выполнить:

```bash
bash scripts/run.sh
```

При запуске Prefect поднимает временный локальный сервер и выполняет
поток `hw_5-team39-orders`. Общий журнал записывается в `build/flow.log`.

Поток состоит из трёх последовательных задач.

1. `Check HDFS input` проверяет наличие непустого файла в HDFS,
   сохраняет его локальную копию для сверки и выводит список узлов YARN.
2. `Spark on YARN` запускает приложение через
   `spark-submit --master yarn --deploy-mode client`.
3. `Verify Hive results` читает результат через Beeline и сравнивает
   его с независимым расчётом по исходным данным.

Кэширование задач отключено. При ошибке любого этапа поток завершается
со статусом `Failed`. Файловая блокировка в `~/venvs/hw_5/pipeline.lock`
предотвращает одновременные запуски через `flow.py` с этим окружением.

## Обработка данных

В одной сессии Spark приложение:

1. Читает TSV из HDFS с явно заданной схемой.
2. Приводит идентификаторы к `BIGINT`, сумму к `DECIMAL(12,2)`,
   дату к `DATE`, убирает пробелы по краям кода страны и переводит
   его в верхний регистр.
3. Группирует данные по дате и стране. Считает количество заказов,
   уникальных покупателей, общую сумму и средний чек.
4. Сохраняет результат через `saveAsTable` в
   `dz5_team39.daily_orders`.

Данные записываются в Parquet со сжатием Snappy и партиционированием
по `order_date` и `country`. Метаданные находятся в общем Hive Metastore.

Каталог результата в HDFS:
`/warehouse/team39/external/dz5_daily_orders`.

При каждом запуске результат полностью заменяется текущим набором.

## Проверка результата

Скрипт `scripts/verify.py` независимо рассчитывает показатели
из локальной копии входного файла, используя `Decimal`.
Затем сравнивает все строки с результатом SQL-запроса
из `sql/inspect.sql`.

Для исходного учебного набора получен следующий результат.

| Дата | Страна | Заказов | Покупателей | Сумма | Средний чек |
| --- | --- | --- | --- | --- | --- |
| 2026-10-20 | KZ | 2 | 2 | 499.90 | 249.95 |
| 2026-10-20 | RU | 2 | 2 | 350.50 | 175.25 |
| 2026-10-21 | KZ | 2 | 2 | 125.75 | 62.88 |
| 2026-10-21 | RU | 2 | 2 | 920.25 | 460.13 |
| 2026-10-22 | KZ | 2 | 2 | 900.60 | 450.30 |
| 2026-10-22 | RU | 2 | 2 | 1200.00 | 600.00 |

Итого получены 6 строк, 12 заказов и сумма `3997.00`.

Проверены два полных запуска потока. Оба получили статус `Completed`.
Повторный запуск завершился с кодом возврата `0`.
Результаты первого и повторного запусков совпали побайтово.
